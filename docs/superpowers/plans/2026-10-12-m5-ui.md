# M5 UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the kit its finished UI shell: one `layouts/base` with server-persisted appearance (DEC-12) and branding, one navigation definition that drives a collapsible sidebar (Overzicht / Beheer / Systeem), a user menu with language and appearance switches, full localisation (locale middleware, guest toggle, profile language, Dutch copy everywhere, translated titles), self-contained localised error pages, a real dashboard (organisation and roles cards, stat cards, recent activity, onboarding checklist), the passkeys module flag, the optional Flux Pro layer with its lint test, and the Pest browser suite. It also closes the M5 follow-ups carried from M2, M3 and M4.

**Architecture:** All pages render through `resources/views/layouts/base.blade.php`. The app and auth layouts wrap it. Small, testable PHP classes under `app/Support` carry the UI rules: `Skv` (module flags, `hasFluxPro()`), `Branding`, `Locales`, `Navigation\*` and `Dashboard\*`. Blade only renders what they return. Settings writes go through single-purpose actions (`App\Actions\Settings\UpdateLocale`, `UpdateAppearance`). Livewire pages keep the M4 rules: authorise in `mount()`, keep `#[Locked]` ids, and read through `HostScope::read()`. The passkeys module mirrors impersonation: a `config('skv.modules.passkeys')` flag decides, during service-provider registration, whether Fortify registers its passkey routes at all. Flux Pro is never a dependency: Pro-only components sit only inside `@if (Skv::hasFluxPro())` branches, which a lint test enforces. The Pro branches are verified once, in a throwaway git worktree where Pro is installed.

**Tech Stack:** PHP 8.4, Laravel 13.35, Livewire 4.4.7 (MFC), Flux 2.20.1 (free; Pro optional), Fortify 1.41, laravel/passkeys 0.2.1, Tailwind 4.3, Pest 5.3, **pestphp/pest-plugin-browser 5.1.2 (new, dev)**, **playwright 1.63 (new, npm dev)**, Larastan 3 level 8, PostgreSQL 18 (Herd), SQLite.

**Spec:** `docs/superpowers/specs/2026-10-10-skv3-design.md`. Read §3, §4.1 (tenant name in the brand), §4.10, §4.11, §6.5, §6.7, §6.8, §7.2 (browser tests), §8 (browser job) and §11.2 (M5 row) before starting. Decisions: `docs/decisions.md` DEC-12, DEC-20 (Pro-only components), DEC-25 (M5 follow-ups), DEC-26 (M5: tenant name, per-user locale), DEC-27 (M5: passkeys flag, Dutch copy, error pages, WebAuthn and Fortify follow-ups) and DEC-28 (M5 deferrals). ## Conventions used in this plan

- All M5 work happens on branch `m5-ui`, created from `main` in Task 1.
- Bracketed ids are traceability tags:
  - `FU2-*`, `FU3-*`, `FU4-*`: follow-ups carried from M2, M3 and M4 (see the inventory below).
  - `RL-*`: rulings in this plan.
  - `OD-*`: owner rulings.
  - `DEC-*`: decision-log entries.
- Test hosts: apex `localhost`, admin `admin.localhost`, tenants `{slug}.localhost`, scheme `http`. Create every model a test needs **before** switching to a central host (strict mode). Call the host helper after the actor helper when they differ (`asSuperAdmin(); onTenant($org);`).
- Browser tests live in `tests/Browser/**`, are in group `browser`, use `RefreshDatabase` on in-memory SQLite (the plugin serves the app in-process), and select a host with `->withHost('acme.localhost')` per visit (RL-2).
  - **`withHost()` applies only to the first page of that visit.** The plugin restores its global host (null) right after building the page, so a later `->navigate('/path')` resolves the relative path against `http://127.0.0.1:PORT`. That is another origin: the host-only session cookie is not sent and tenancy sees an unknown host. After the first page, **always navigate to an absolute URL on the current origin**: `$page->navigate(sameOrigin($page->url(), '/users'))`. Split the chain where `$page` is needed. A second `visit()` is no workaround: every visit opens a fresh browser context without cookies.
  - The plugin's `assertSee` / `assertDontSee` search visible text only. Assert the presence or absence of an element with `assertPresent('@x')` / `assertMissing('@x')` (`@x` matches `data-test="x"`), never with an attribute string in `assertDontSee`.
- Facts verified for this plan by vendor reads, docs and a Tailwind compile (2026-10-12):
  - Plugin `pestphp/pest-plugin-browser` v5.1.2 needs `pestphp/pest ^5.2.1`, `ext-sockets` and npm `playwright ^1.63.0`.
    - It serves the app from an Amp server inside the test process (`127.0.0.1`, free port), shares the container and DB connection, forces `app.debug=false`, and syncs `app.url` / the URL origin to each request's origin.
    - `visit($path)->withHost($host)` sends `Host: $host:PORT`.
    - Tests under `tests/Browser` (or calling `visit()`) are browser tests.
  - `@fluxAppearance` prints `window.Flux.applyAppearance()` and applies `localStorage['flux.appearance'] || 'system'`.
    - `'system'` removes the key.
    - Flux's JS exposes a reactive `$flux.appearance` and dispatches no change event.
  - Flux accent presets come from fluxui.dev/themes, as light accent / content / foreground ‖ dark accent / content / foreground; table in Task 4.
    - Tailwind 4.3 emits a colour variable when `var(--color-x-n)` appears anywhere in `app.css`, so no `@theme static` is needed.
  - Free Flux has `sidebar.{backdrop,brand,collapse,group,header,index,item,nav,profile,search,spacer,toggle}`, `navlist.*` and `menu.*`. The free `select` has only the default (native) variant.
  - Livewire `#[Title('x')]` passes `x` to the layout's `$title`. Attributes cannot call `__()`, and `$this->view()->title()` is banned here, so the layout translates `__($title)` (RL-9).
  - Livewire update requests send no `Accept: application/json`, so `expectsJson()` is false and HTML error pages render in Livewire's modal.
    - A `render()` method on an exception runs before the JSON check.
    - `dontReport()` matches subclasses (`instanceof`).
  - Fortify registers its routes in `boot()` under `Route::group(['domain' => config('fortify.domain'), 'prefix' => config('fortify.prefix')])` with path names from `RoutePath::for()`.
    - App routes load later, and a route with the same method + domain + URI replaces the earlier one.
  - Passkey routes are registered by Fortify (`routes/routes.php`) only when `Features::passkeys()` is in `config('fortify.features')` **when Fortify boots**. `Features::canManagePasskeys()` reads the config live.
    - laravel/passkeys reads `passkeys.relying_party_id` and `passkeys.allowed_origins` at request time.
  - `Application::setLocale()` also writes `config('app.locale')`, so `Locale::default()` must not read `app.locale` once the middleware runs (RL-8).

## Rulings

- **RL-1:** `App\Support\Skv` is a final class with static methods: `hasFluxPro()`, `passkeysEnabled()` and `impersonationEnabled()`.
  - It is registered as the global alias `Skv` in `AppServiceProvider::register()` (`AliasLoader`), so Blade can write `@if (Skv::hasFluxPro())` as the spec does.
  - `hasFluxPro()` caches `InstalledVersions::isInstalled('livewire/flux-pro')` in a static property.
  - `Skv::useFluxPro(?bool)` overrides that value for tests: `false` forces the free branch even where Pro is installed; `null` resets.
- **RL-2:** browser tests pick a host per visit with `->withHost()`. A global `withHost()` is never set: it would also change the bind host of the Playwright server.
  - If the Task 1 spike shows that Chromium does not reach `{slug}.localhost`, tenant-host browser tests are written against the apex and admin host only. The cross-subdomain appearance check then runs as an HTTP test, and DEC-29 says so.
  - Browser tests force the Vite manifest with `Vite::useHotFile(storage_path('framework/testing/no-vite-hot'))`, so a running `npm run dev` (`public/hot`) never leaks dev-server URLs into a browser run. `composer test:browser` fails early with the fix command when `public/build/manifest.json` or Playwright is missing.
- **RL-3:** the passkeys module (§6.8):
  - `config('skv.modules.passkeys')` (`MODULE_PASSKEYS`, default true) is the only flag.
  - `AppServiceProvider::register()` removes `Features::passkeys()` from `fortify.features` when it is off. This runs before Fortify boots, so Fortify registers no passkey routes and `Features::canManagePasskeys()` is false.
  - `.well-known/passkey-endpoints` moves to `routes/passkeys.php`, required only while the module is on.
  - The `passkeys` rate limiter and the `SetPasskeyOrigin` listeners are registered only while it is on.
  - The login and confirm-password pages render `<x-passkey-verify>` only while it is on.
  - The HTTPS consequence ("HTTPS no longer forced") is M6's setup logic. The second-factor consequence is M7.
  - `usePasskeysModule(bool)` (Task 2) mirrors `useImpersonationModule()`. Every existing test that needs passkeys calls `usePasskeysModule(true)` first, because the `sqlite-free` CI job boots the suite with `MODULE_PASSKEYS=false`.
- **RL-4:** `layouts/base.blade.php` is the only file with `<html>`, `<head>`, `@vite`, `@fluxAppearance`, the toast group, the flash→toast bridge and `@fluxScripts`.
  - The inline appearance script before `@fluxAppearance` sets `localStorage['flux.appearance']` from `users.appearance`, or removes it for `system` and for guests.
  - `<html>` gets `class="dark"` server-side only when the stored value is `dark`.
  - Logout needs no extra code: the next guest page removes the key.
  - The impersonation banner stays **inside `flux:main`** in the app layout. Flux's sidebar layout is a CSS grid on `<body>`, and an extra body child breaks it. The auth layout renders it above the card, so a password confirmation during an impersonation still shows the banner. This refines DEC-28's "the banner moves to base" and is recorded in DEC-29.
- **RL-5:** branding.
  - `config/branding.php` has three keys:
    - `name` (`APP_NAME`)
    - `logo` (`BRANDING_LOGO`, a path under `public/`, nullable)
    - `accent` (`BRANDING_ACCENT`, default `neutral`)
  - `App\Support\Branding::accent()` returns a value from `Branding::ACCENTS` (the Flux presets plus `neutral`) and falls back to `neutral`.
  - `<html data-accent="…">` selects the preset rules in `app.css`.
  - `Branding::name()` is the organisation's name on a tenant host and the platform name centrally (§4.1). `Branding::platformName()` is always the platform.
  - `Branding::isCustomised()` (accent not `neutral`, or a logo set) completes the "set branding" checklist item.
  - M5 adds no branding page. Setup step 4 (M6) writes the env keys.
  - Mails stay light and unbranded beyond the name.
- **RL-6:** navigation.
  - `App\Support\Navigation\NavigationItem` is a readonly value object: route, label key, icon, `?Permission`, route-match pattern, `App\Enums\NavigationGroup`, `?string $module`, `bool $centralOnly`. The enum lives in `App\Enums`: the Laravel arch preset (`tests/Arch/PresetsTest.php`) forbids enums elsewhere in `App`.
  - `Navigation::items()` returns the kit's list. `Navigation::visible(list $items, User $user)` is the pure filter: permission via `$user->can()`, module via `Skv::moduleEnabled()`, `centralOnly` via `Tenant::check()`. `Navigation::for(User $user)` returns the visible items grouped in `NavigationGroup` order, leaving out empty groups.
  - Groups and items:
    - Overview ("Overzicht"): Dashboard.
    - Management ("Beheer"): Users, Pending invitations, Organisations, Roles.
    - System ("Systeem"): Activity log. M7 adds the System page there.
  - No M5 item has a module. The module filter is covered by a unit test with a constructed item.
  - The sidebar is `flux:sidebar sticky collapsible`, collapsible on desktop too, with `flux:sidebar.collapse`. Each item carries `data-test="nav-{route}"`.
  - The starter's Repository and Documentation links are removed.
- **RL-7:** the user menu is one reusable Livewire component, `<livewire:user-menu :variant="'sidebar'|'header'" />`. It holds the profile header, Settings, the Language radio group (`Locale::cases()`), the Appearance radio group (`$flux.appearance`, saved through `$wire`) and Log out.
  - Changing the language saves `users.locale` through `App\Actions\Settings\UpdateLocale` and reloads the current page from a `#[Locked]` path captured in `mount()`. The page is never rebuilt from the Referer.
  - Changing the appearance saves through `App\Actions\Settings\UpdateAppearance`.
  - Neither change is audited: they are display preferences, not in the §4.8 list.
- **RL-8:** locales.
  - `App\Enums\Locale` stays the single list.
  - `Locale::default()` reads `config('skv.locale.default')`, set once from `APP_LOCALE` in `config/skv.php` (default `nl`), because `setLocale()` overwrites `app.locale` during a request. `.env.example` keeps `APP_LOCALE=nl`; `phpunit.xml` keeps `APP_LOCALE=en`, so tests default to English.
  - `App\Support\Locales::forRequest(Request)` decides in this order: the signed-in user's `locale`, then the session `locale` (guest toggle), then the best `Accept-Language` match among `Locale::cases()`, then `Locale::default()`.
  - `App\Http\Middleware\SetLocale` runs in the web group, appended after `AuthenticateSession`. It sets the app locale and `Date::setLocale()`. It covers Livewire updates too, because Livewire's update route uses the web group.
  - The invitation accept page keeps its invitee locale (`useInviteeLocale()` runs in the component after the middleware).
  - `POST /locale` (`locale.update`, any host, guest or signed in) stores the choice in the session for guests, or through `UpdateLocale` for users, then redirects `back()`. The auth layout shows the toggle.
- **RL-9:** titles stay English literals in `#[Title('…')]` and are translation keys. `layouts/base` renders `__($title)`. `LangCoverageTest` also extracts `#[Title('…')]` values.
- **RL-10:** error pages.
  - `resources/views/errors/layout.blade.php` is self-contained: inline CSS, a dark mode via `prefers-color-scheme`, no `@vite`, no Flux, no Livewire.
  - `403`, `404`, `419`, `429`, `500`, `503`, `tenant-not-found` and `invitation-invalid` extend it.
  - A view composer on `errors::*` and `errors.*` sets the locale through `Locales::forRequest()`. 404s for unknown routes never run the web middleware, so the user is unknown there and `Accept-Language` decides.
  - Actions:
    - 403: "Back" (`url()->previous()`), plus "Go to your organisation" (the user's home host, for signed-in users who have one) or "Log in" for guests.
    - 404: "Go to the home page".
    - 419: "Reload the page" and "Log in".
    - 429: "Try again in a minute".
    - 500 / 503: "Try again".
  - The invitation accept page throws `App\Exceptions\InvitationNotFoundException`, rendered as `errors.invitation-invalid` with status 404, instead of `abort(404)`.
  - `TenantNotFoundException::render()` answers JSON (`{"message": …}`, 404) when `expectsJson()`, and HTML otherwise, Livewire updates included (FU2-1).
- **RL-11:** the dashboard is a Livewire page, `pages::dashboard`. `Route::livewire('dashboard', 'pages::dashboard')` keeps the route name and middleware. It shows:
  - The Organisation card: the tenant's name, or "Platform" centrally.
  - "Your roles": translated system-role labels, or custom role names, read through the current team; "No roles assigned" when empty.
  - Stat cards, each shown only with its permission:
    - Users and Pending invitations: `users.view`, through `HostScope::read()`.
    - Organisations: `organisations.view`, central hosts only.
  - Recent activity: `activity_log.view`. The last 10 entries through `HostScope::read()`, with the event label, the causer's name (`UserNames::of()`) and the relative time. It shows no IP address, user agent or field changes, so DEC-28 (7)'s privacy rules are met without copying the viewer's row logic.
  - The onboarding checklist (`App\Support\Dashboard\OnboardingChecklist`):
    - For super admins on central hosts: create an organisation, invite an organisation's first admin, enable two-factor authentication, set branding.
    - For organisation admins on their tenant host: invite a colleague, enable two-factor authentication.
    - Hidden when every item is done.
  - With Pro, a logins-over-14-days chart (Task 12).
- **RL-12:** the Pro variants. Each keeps the free branch's Livewire properties:
  - Role assignment (users edit, invite): `flux:select variant="listbox" multiple` on the same `array $roles`.
  - Active / archived (users index, organisations index): `flux:tabs variant="segmented"` with `wire:model.live="view"`.
  - The audit date filter: two single `flux:date-picker`s on `from` and `until`. A range picker would bind one value and break "identical properties". DEC-29 records this refinement of §6.7's "date-picker range".
  - The ⌘K `flux:command` palette, listing `Navigation::for()`.
  - The `flux:chart` login trend on the dashboard.
  - Upload variants are M7.

```php
/**
 * An active user for browser tests, password "password": a member of $organisation, or a super admin.
 * Signs nobody in: the browser signs in through the login page on the host it visits.
 */
function browserUser(?Organisation $organisation = null, string $email = 'member@example.com', bool $superAdmin = false): User
{
    if ($superAdmin) {
        $user = User::factory()->superAdmin()->create(['email' => $email]);
        app(SetSuperAdmin::class)->handle($user, true);

        return $user;
    }

    return User::factory()->for($organisation ?? Organisation::factory()->create())->create(['email' => $email]);
}

/**
 * The absolute URL of $path on the origin of $currentUrl (pass $page->url()). The browser plugin resolves a
 * relative navigate() path against 127.0.0.1, not the withHost() host, which drops the host-only session (RL-2).
 */
function sameOrigin(string $currentUrl, string $path): string
{
    return (string) Uri::of($currentUrl)->withPath($path)->withQuery([], merge: false)->withoutFragment();
}
```

After `useImpersonationModule()`:

```php
/**
 * Turns the passkeys module on or off for the rest of the test (§6.8, RL-3): the flag, Fortify's passkeys
 * feature and the passkey routes, as they would be at boot for that value. The sqlite-free CI job boots the
 * suite with MODULE_PASSKEYS=false, so every test that needs passkeys calls this first. Fortify registers
 * its routes from one file, so "on" replays that file on a scratch router (through the Route facade) and
 * copies only the passkey routes; "off" swaps in a copy without them.
 */
function usePasskeysModule(bool $enabled): void
{
    config(['skv.modules.passkeys' => $enabled]);

    /** @var list<string> $features */
    $features = config('fortify.features', []);
    $withoutPasskeys = array_values(array_filter($features, fn (string $feature): bool => $feature !== Features::passkeys()));
    config(['fortify.features' => $enabled ? [...$withoutPasskeys, Features::passkeys(['confirmPassword' => true])] : $withoutPasskeys]);

    $router = app(Router::class);
    $isPasskeyRoute = fn (?string $name): bool => $name !== null && (str_starts_with($name, 'passkey.') || $name === 'well-known.passkeys');

    if ($enabled && ! $router->getRoutes()->hasNamedRoute('passkey.login-options')) {
        $scratch = new Router(app('events'), app());
        Route::swap($scratch);

        try {
            $scratch->group([
                'namespace' => 'Laravel\Fortify\Http\Controllers',
                'domain' => config('fortify.domain'),
                'prefix' => config('fortify.prefix'),
            ], base_path('vendor/laravel/fortify/routes/routes.php'));
            $scratch->middleware('web')->group(base_path('routes/passkeys.php'));
        } finally {
            Route::swap($router);
        }

        foreach ($scratch->getRoutes()->getRoutes() as $route) {
            if ($isPasskeyRoute($route->getName())) {
                $router->getRoutes()->add($route);
            }
        }
    }

    if (! $enabled) {
        $kept = new RouteCollection;

        foreach ($router->getRoutes()->getRoutes() as $route) {
            if (! $isPasskeyRoute($route->getName())) {
                $kept->add($route);
            }
        }

        $router->setRoutes($kept);
    }

    $router->getRoutes()->refreshNameLookups();
    $router->getRoutes()->refreshActionLookups();
}
```

```php
    /** @return list<NavigationItem> */
    public static function items(): array
    {
        return [
            new NavigationItem('dashboard', 'Dashboard', 'home', null, 'dashboard', NavigationGroup::Overview),
            new NavigationItem('users.index', 'Users', 'users', Permission::UsersView, 'users.*', NavigationGroup::Management),
            new NavigationItem('invitations.pending', 'Pending invitations', 'envelope', Permission::UsersView, 'invitations.pending', NavigationGroup::Management),

            new NavigationItem('activity.index', 'Activity log', 'clipboard-document-list', Permission::ActivityLogView, 'activity.*', NavigationGroup::System),
        ];
    }

    /**
     * The items this user may use on this host with the current module flags.
     *
     * @param  list<NavigationItem>  $items
     * @return list<NavigationItem>
     */
    public static function visible(array $items, User $user): array
    {
        return array_values(array_filter($items, fn (NavigationItem $item): bool => ($item->permission === null || $user->can($item->permission))
            && ($item->module === null || Skv::moduleEnabled($item->module))
            && (! $item->centralOnly || ! Tenant::check())));
    }

    /** @return list<array{group: NavigationGroup, items: list<NavigationItem>}> */
    public static function for(User $user): array
    {
        $visible = self::visible(self::items(), $user);
        $groups = [];

        foreach (NavigationGroup::cases() as $group) {
            $items = array_values(array_filter($visible, fn (NavigationItem $item): bool => $item->group === $group));

            if ($items !== []) {
                $groups[] = ['group' => $group, 'items' => $items];
            }
        }

        return $groups;
    }
}
```

`app/Support/Locales.php`:

```php
<?php

declare(strict_types=1);

namespace App\Support;

use App\Enums\Locale;
use App\Models\User;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Date;

/** Which language a request is answered in (§4.11, RL-8). */
final class Locales
{
    /** The signed-in user's language, else the guest's choice, else the browser's preference, else the default. */
    public static function forRequest(Request $request): Locale
    {
        $user = $request->user();

        if ($user instanceof User) {
            return $user->locale;
        }

        if ($request->hasSession()) {
            $chosen = Locale::tryFrom((string) $request->session()->get('locale'));

            if ($chosen instanceof Locale) {
                return $chosen;
            }
        }

        $supported = array_map(fn (Locale $locale): string => $locale->value, Locale::cases());
        $preferred = $request->getPreferredLanguage($supported);
        $accepted = Locale::tryFrom((string) $preferred);

        // getPreferredLanguage() falls back to the first supported value when nothing matches.
        return $accepted instanceof Locale && self::browserAsksFor($request, $accepted) ? $accepted : Locale::default();
    }

    public static function apply(Locale $locale): void
    {
        app()->setLocale($locale->value);
        Date::setLocale($locale->value);
    }

    private static function browserAsksFor(Request $request, Locale $locale): bool
    {
        foreach ($request->getLanguages() as $language) {
            if (str_starts_with(strtolower($language), $locale->value)) {
                return true;
            }
        }

        return false;
    }
}
```

`$request->user()` returns the guard's user. During an impersonation that is the target, so the impersonator sees the target's language. That is intended: they see what the target sees.

```php
<?php

declare(strict_types=1);

namespace Tests\Support;

use Illuminate\Support\Facades\File;

/**
 * §6.7 / RL-13: Pro-only Flux components may appear only in the true branch of `@if (Skv::hasFluxPro())`.
 * A tag is free when free Flux (or a project override) has its view, or when it is an icon; `flux:select`
 * with a Pro variant is Pro (DEC-25).
 */
final class FluxProLint
{
    private const string PRO_CONDITION = '/^@(if|elseif)\s*\(\s*\\\\?(App\\\\Support\\\\)?Skv::hasFluxPro\(\)\s*\)/';

    /** @var list<string>|null */
    private static ?array $free = null;

    /** @return list<string> */
    public static function violations(string $blade): array
    {
        $violations = [];
        $stack = []; // each entry: ['pro' => bool, 'else' => bool]

        foreach (preg_split('/\R/', $blade) ?: [] as $index => $line) {
            foreach (self::tokens($line) as $token) {
                if (str_starts_with($token, '@')) {
                    self::directive($token, $stack);

                    continue;
                }

                if (! self::insidePro($stack) && self::isPro($token)) {
                    $violations[] = 'line '.($index + 1).': '.$token;
                }
            }
        }

        return $violations;
    }

    /** @return list<string> Free component names such as "sidebar.item" or "button". */
    public static function freeComponents(): array
    {
        if (self::$free !== null) {
            return self::$free;
        }

        $names = [];

        foreach ([base_path('vendor/livewire/flux/stubs/resources/views/flux'), resource_path('views/flux')] as $root) {
            if (! is_dir($root)) {
                continue;
            }

            foreach (File::allFiles($root) as $file) {
                $relative = str_replace(DIRECTORY_SEPARATOR, '/', $file->getRelativePathname());
                $name = preg_replace(['/\.blade\.php$/', '#/index$#'], '', $relative);
                $names[] = str_replace('/', '.', (string) $name);
            }
        }

        return self::$free = array_values(array_unique($names));
    }

    /** @return list<string> Blade directives and opening flux tags, in order. */
    private static function tokens(string $line): array
    {
        preg_match_all('/@(?:if|elseif|else|endif|unless|endunless)\b(?:\s*\((?:[^()]|\((?:[^()]|\([^()]*\))*\))*\))?|<flux:[a-z0-9.\-]+(?:\s[^>]*)?>?/i', $line, $matches);

        return $matches[0];
    }

    /** @param  list<array{pro: bool, else: bool}>  $stack */
    private static function directive(string $token, array &$stack): void
    {
        if (preg_match('/^@(if|unless)\b/', $token) === 1) {
            $isPro = preg_match(self::PRO_CONDITION, $token) === 1;
            $stack[] = ['pro' => $isPro && str_starts_with($token, '@if'), 'else' => false];

            return;
        }

        if (preg_match('/^@(else|elseif)\b/', $token) === 1 && $stack !== []) {
            // One whole-frame assignment keeps the frame's array shape for Larastan (parameterByRef.type).
            $last = array_key_last($stack);
            $stack[$last] = ['pro' => false, 'else' => true];

            return;
        }

        if (preg_match('/^@(endif|endunless)\b/', $token) === 1) {
            array_pop($stack);
        }
    }

    /** @param  list<array{pro: bool, else: bool}>  $stack */
    private static function insidePro(array $stack): bool
    {
        foreach ($stack as $frame) {
            if ($frame['pro'] && ! $frame['else']) {
                return true;
            }
        }

        return false;
    }

    private static function isPro(string $tag): bool
    {
        preg_match('/^<flux:([a-z0-9.\-]+)/i', $tag, $match);
        $name = strtolower($match[1] ?? '');

        if ($name === '' || str_starts_with($name, 'icon.') || $name === 'icon') {
            return false;
        }

        if ($name === 'select' && preg_match('/\bvariant\s*=\s*"(listbox|combobox|custom)"/', $tag) === 1) {
            return true;
        }

        return ! in_array($name, self::freeComponents(), true);
    }
}
```

- Tags that span several lines are matched by their first line only. That is enough, because the variant attribute must sit on the opening line of a `flux:select`. Add that rule as a comment.

`app/Support/Dashboard/LoginTrend.php`:

```php
<?php

declare(strict_types=1);

namespace App\Support\Dashboard;

use App\Enums\ActivityEvent;
use App\Models\Activity;
use App\Tenancy\HostScope;
use Carbon\CarbonInterface;

/** Sign-ins per day on this host's scope, for the dashboard chart (§6.5, RL-15). Grouped in PHP: portable SQL. */
final class LoginTrend
{
    /** @return list<array{date: string, logins: int}> */
    public static function lastDays(int $days = 14): array
    {
        $start = now()->startOfDay()->subDays($days - 1);

        /** @var list<CarbonInterface> $moments */
        $moments = HostScope::read(fn (): array => Activity::query()
            ->where('event', ActivityEvent::Login->value)
            ->where('created_at', '>=', $start)
            ->pluck('created_at')
            ->all());

        $counts = [];

        foreach ($moments as $moment) {
            $day = $moment->toDateString();
            $counts[$day] = ($counts[$day] ?? 0) + 1;
        }

        $trend = [];

        for ($offset = 0; $offset < $days; $offset++) {
            $day = $start->addDays($offset)->toDateString();
            $trend[] = ['date' => $day, 'logins' => $counts[$day] ?? 0];
        }

        return $trend;
    }
}
```
