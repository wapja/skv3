1Introductie

skv3 is een multi-tenant Laravel starter kit en de opvolger van skv2. Elke organisatie krijgt een eigen subdomein. De kit levert uitnodigingen, rollen en rechten, ‘inloggen als’, een activiteitenlog en een Flux UI. Alles draait op één database: de organisatie volgt uit het subdomein van het verzoek.

De basis is de officiële Laravel Livewire starter kit: PHP 8.4, Laravel 13, Livewire 4, Flux 2 (de gratis versie), Fortify voor inloggen, en de Spatie-pakketten voor rechten en het activiteitenlog. Tests schrijf je met Pest 5.

Drie soorten hosts

Elke host is een adres onder het apex-domein. Dat apex is TENANCY_APEX_DOMAIN, of als die leeg is de host uit APP_URL. In alle voorbeelden in deze handleiding staat de app in de map mijnapp, is het apex mijnapp.test en heet de organisatie acme.

  • Een adres dat geen apex, geen admin-host en geen bestaande organisatie is, geeft een nette 404: Organisatie niet gevonden met de knop Naar de hoofdsite.
  • Het organisatieadres (in de app het veld Adres, in de code slug) is het deel vóór het apex: acme in acme.mijnapp.test. Het is één DNS-label van 3 tot 63 tekens (a-z, 0-9, -), zonder koppelteken aan begin of eind. Een aantal woorden is gereserveerd, zoals admin, www, api en login.
  • Iedere gebruiker hoort bij precies één organisatie. Superbeheerders hebben meestal geen organisatie.
  • Sessies gelden per host. Wie op acme.mijnapp.test is ingelogd, is dat niet automatisch op admin.mijnapp.test.

Installeren via Herd (aanbevolen)

Herd serveert de site, dus je draait nooit php artisan serve. Herd serveert elke map in ~/Herd als <map>.test, inclusief subdomeinen: de map mijnapp antwoordt op mijnapp.test, admin.mijnapp.test en acme.mijnapp.test, zonder extra instellingen (gecontroleerd in de smoke test van M4).

  1. Zet de code in een map die Herd serveert. De naam van de map wordt het adres.

    cd ~/Herd
git clone <repository-url> mijnapp
cd mijnapp

  2. Draai de setup. Dit installeert de PHP-pakketten, maakt .env aan uit .env.example (alleen als .env nog niet bestaat), genereert een APP_KEY (alleen als die leeg is), maakt database/database.sqlite, migreert, haalt de Boost-richtlijnen op, zet de git-hooks aan en draait npm ci en npm run build. Zonder Node en npm loopt de setup hier vast.

    composer setup

    Liever PostgreSQL dan SQLite? Doe dit vóór composer setup

    composer setup migreert naar de database in .env, en dat is standaard SQLite. Wil je PostgreSQL, maak dan eerst zelf de .env aan; de setup laat een bestaande .env staan.

    cp .env.example .env

    Haal in .env het #-teken weg bij de regels DB_HOST tot en met DB_PASSWORD en zet:

    DB_CONNECTION=pgsql
DB_PORT=5432
DB_DATABASE=mijnapp

    Verander 3306 in 5432. In .env.example staat DB_PORT=3306, de MySQL-poort. Laat je de regels in commentaar, dan gelden de PostgreSQL-standaarden van de kit: 127.0.0.1, 5432, database laravel, gebruiker root en een leeg wachtwoord. Herd Pro gebruikt gebruiker root zonder wachtwoord.

    De database zelf moet al bestaan. Maak hem bijvoorbeeld met createdb -U root mijnapp of via TablePlus niet in de repo geverifieerd. Draai daarna composer setup.

  3. Zet APP_URL op het Herd-adres. .env.example begint met http://localhost. Laat je dat staan, dan is het apex localhost en geeft mijnapp.test de pagina Organisatie niet gevonden.

    APP_NAME="Mijn App"
APP_URL=http://mijnapp.test

    Heb je de config gecachet, draai dan php artisan config:clear. APP_NAME staat standaard op Laravel; die naam zie je in de zijbalk, de paginatitel en als afzender van mails.

  4. Maak het ontwikkelaccount aan. composer setup seedt niet; dat doe je één keer zelf.

    php artisan db:seed

  5. Start de ontwikkelprocessen en open http://admin.mijnapp.test/login.

    composer dev

Valkuilen

  • APP_URL moet kloppen met het adres in je browser, inclusief http of https. Het apex komt eruit, en mails die de worker bouwt nemen het schema van APP_URL over.
  • Mails worden niet echt verstuurd. MAIL_MAILER=log schrijft ze naar het log. Wil je ze in Herd Pro-mail zien, zet dan in .env MAIL_MAILER=smtp; MAIL_HOST=127.0.0.1 en MAIL_PORT=2525 staan al in .env.example Herd-poort 2525 niet in de repo getest. Uitnodigings- en e-mailwijzigingsmails gaan via de wachtrij, dus de queue-worker (composer dev) moet draaien.
  • Bewaar je APP_KEY. De geheimen van tweestapsverificatie en passkeys hangen ervan af. composer setup laat een bestaande sleutel staan. Na het wisselen van de sleutel moet je openstaande uitnodigingen intrekken en opnieuw versturen.
  • Passkeys willen https. Browsers staan WebAuthn alleen toe in een beveiligde context algemene browserregel, niet getest in de repo. Beveilig de site in Herd en zet APP_URL dan op https://. Controleer daarna dat ook acme.mijnapp.test een geldig certificaat heeft niet geverifieerd.
  • Leden loggen alleen in op hun eigen organisatie. Een lid op het apex of de admin-host krijgt dezelfde foutmelding als bij een verkeerd wachtwoord.
  • Er staan nog geen geplande taken. schedule:list is leeg. Opruimen van het log doe je met de hand: php artisan activitylog:clean.
  • Sterke wachtwoorden alleen in productie. Daar geldt minimaal 12 tekens, hoofd- en kleine letters, cijfers, symbolen en niet gelekt. Lokaal is alleen een minimum van 8 tekens verplicht.
  • migrate:fresh en db:wipe wissen je ontwikkeldata. De tests hebben hun eigen database, dus voor de tests is dat nooit nodig. Moet je een oude ontwikkeldatabase toch opnieuw opbouwen, maak dan eerst een kopie van database/database.sqlite en draai php artisan migrate:fresh --seed.
  • Werk je met een AI-agent? CLAUDE.md verbiedt agents migrate:fresh en db:wipe op de ontwikkeldatabase, en laat ze vragen voor tinker, migrate en db:seed. Ze draaien ook nooit herd sites of de Herd MCP-tool get_all_sites: die tonen de .env van al je sites, met geheimen.
  • De tests trekken zich niets aan van je .env-hosts. phpunit.xml zet het apex vast op localhost.

Tweestapsverificatie en herstelcodes

Je beheert de tweede stap op de beveiligingspagina: klik linksonder in de zijbalk op je naam (op een telefoon: je initialen rechtsboven), dan Settings en Security (/settings/security). Die pagina vraagt eerst je wachtwoord (Wachtwoord bevestigen). Een bevestiging blijft 3 uur geldig; elke gevoelige actie controleert dat opnieuw.

  1. Klik Enable 2FA. Scan de QR-code met je authenticator-app, of kies or, enter the code manually, en klik Continue.

  2. Vul de 6-cijferige code in en klik Confirm (met Terug ga je een stap terug). Het venster sluit en de pagina toont nu Disable 2FA en je herstelcodes.

  3. Bewaar je herstelcodes: View recovery codes, dan Kopiëren of Downloaden (een bestand recovery-codes.txt, één code per regel).

Bij het inloggen vraagt de pagina Two-factor authentication om je code. Kwijt? Kies login using a recovery code. Elke herstelcode werkt één keer. Met Codes opnieuw genereren maak je nieuwe; de vraag Herstelcodes opnieuw genereren? waarschuwt dat de oude dan niet meer werken. Uitzetten doe je met Disable 2FA.

Ook je wachtwoord wijzig je hier: onder Update password vul je Current password, New password en Wachtwoord bevestigen in, en klik je Opslaan.

Passkeys

Met een passkey log je in zonder wachtwoord. Het relying party id is altijd het apex, dus één passkey werkt op het apex, de admin-host en elke organisatiehost, en blijft werken als het webadres van je organisatie verandert.

  • Toevoegen: op de beveiligingspagina (Settings → Security) onder Passkeys klik je Add passkey, geef je een Passkey name (bijvoorbeeld ‘MacBook Pro’) en klik je Register passkey.
  • Inloggen: Sign in with a passkey op de inlogpagina. Ook dan geldt de hostregel.
  • Mislukt de controle, dan zie je Deze passkey kon niet worden geverifieerd.
  • Verwijderen vraagt een verse wachtwoordbevestiging.
  • Passkeys staan nu altijd aan. Een schakelaar MODULE_PASSKEYS komt in M5.
